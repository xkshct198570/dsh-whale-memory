![Whale Memory](preview.svg)

DeepSeek Harness のセッション向けのローカル長期記憶です。毎ターンの前に想起し、内容を確認できるパネルを備え、ルールの真実源はローカルの git Markdown リポジトリに置きます。データベースは検索用のミラーにすぎません。

## 機能

1. **自動想起** — 毎ターンの前にローカル記憶を検索し、関連する記憶を意図別の予算（チャット 3 / トラブルシュート 5 / 想起 4 / 画像 0）の範囲で注入します。2 秒でタイムアウトした場合は、応答を止めずにそのターンの注入をスキップします。
2. **ローカル長期ストア** — ノードは階層・種類・バイテンポラル項目・ワークスペース分離を持ち、既定ではローカルの SQLite（`$DSH_HOME/whale-memory/memory.db`）に保存します。外部サービスは不要です。
3. **6 タブのパネル** — 概要、記憶（検索・編集・アーカイブ・インポート・エクスポート）、想起、書き込みとリレーション、ルール、設定。ルールタブには提案、履歴の diff とロールバック、git 状態、`/rules/health` があります。
4. **統制された書き込み** — 1 件の記憶は 500 文字以内。直接書き込みは既定でシャドー審査、締め処理の長期記憶は価値ゲートを通れば自動で入ります（タスク指示・バージョン状態は拒否、曖昧なものは審査へ。`review` に切り替えると全件がシャドー）。JSONL のインポート／エクスポートに対応し、監査記録を保持します。
5. **バージョン管理されたルール** — 鉄律は `~/.dsh/rules/` の Markdown ファイルに置きます。提案 → 計画と適用 → 1 コミット、の順に進みます。完全削除は墓碑を書き込み、その番号は再利用されません。データベースのミラーはパネル専用で、想起の対象外です。
6. **セッション締め v2** — 「締める」「セッションを切り替える」などの発話、アイドル（カードのスイッチ）、セッション終了のときに、教訓・決定・未完了を 1 回の範囲付き抽出でまとめます。セッション選択、クリック即待機（202+進捗）、セッション単位の自動締めスキップに対応。任意の整合（Reconcile、既定オフ）は候補を既存記憶と照合し、ADD/UPDATE/MERGE/ARCHIVE の shadow 決定だけを生成します。曖昧・低信頼の候補は shadow のまま、長期記憶は自動で入ります。ルールは提案にだけなり、レポートには生の会話を含めません。
7. **レイヤーと初回プロファイル** — 締め／内省の書き込みは `fact`/`lesson`/`user` のレイヤーを持ちます（パネルからの直接書き込みと旧行は NULL のまま、`memory_*` ツール書き込みはレイヤーを持ちます）。セッションの初回ターンで、同じ身元の `user` 上位 5 / `lesson` 上位 5 / `fact` 上位 3 から 800 文字以内のプロファイルを作り 1 回だけ注入します。2 回目以降は出ません。サブエージェントや身元不明時はスキップし、失敗はログだけ残します。
8. **モデル側ツールと自動内省** — モデルは `memory_remember/search/read/update/forget` を直接呼べます（身元は現在のセッション固定、ターンごとの書き込み上限あり、別パーティションの id は不存在扱い）。自動内省は 1 ターンのツール実行が 7 ステップ以上、またはアイドル時に走ります。既定オフで、ローカル日ごとの上限と `maintenance.suppressWindows` のピーク時間帯で抑制されます（手動は両方を迂回しますが身元は必須）。
9. **移行** — `migrate-audit` は読み取り専用の突き合わせを行い、リレーションエッジを移行する前にバックアップします。詳細は `docs/MIGRATION.md`。

## インストール

- Plugins マーケットで `dsh-whale-memory` を検索します（掲載後）。
- またはリリースの tarball をインストールします：`dsh plugin --profile <profile> add <dsh-whale-memory.tgz>`
- ローカル開発では `link:<repository-directory>` を使います。
- DSH `>=0.2.2-rc.5 <0.3.0`、Node `>=22.13.0` が必要です。

## 使い方

1. 導入後すぐに動きます：ローカルストアと自動想起が有効で、API キーも外部サービスも要りません。
2. 「これからは〜する」と言うとルールの草案を作ります → `收录 <p...>` と返信するか、ルールタブで確認します。適用前にファイル単位のガード付き計画が表示されます。
3. ルールタブでは作成・編集・退役・完全削除、履歴の diff とロールバックができます。`/rules/health` はファイル、manifest、墓碑、チェーン、番号を検査します。
4. グローバルルールは `AGENTS.md` に描画されます。クリーンインストール時はプラグインが最小限の管理ブロックを作成し、マーカーのない既存ファイルには追記しません。

## プライバシーと制限

既定ではデータはローカルに留まります。バックエンドを手動で `http`/`hybrid` に設定した場合だけ、統計・直近・検索・想起・書き込み・バージョンの各リクエストを設定 URL へ送ります。テレメトリも外部へのコピーもありません。締め処理の生素材は 0600 の一時 spool にだけ置き（既定 24 時間で自動削除、バックアップ対象外）、レポート・ログ・状態には生の会話を含めません。想起はフェイルオープンで、グローバルルールは AGENTS ダイジェストに依存します。`rules.llm=false` のとき、統合・競合の候補はパネルでの書き換えが必要です。
