## 1.1 身份与分区隔离

### P0-01 空身份字段＝"不过滤"（fail-open）：live 默认 `workspace=''` ⇒ 列表/详情/导出/审计跨工作区

- **严重度**：P0
- **模块**：`src/core/backend/base.js`、`src/core/search.js`、`src/host/routes/router.js`、`src/host/identity.js`
- **现象**：`identityFilter` 对空串列直接 `continue` 丢弃该列条件；`identityParams` 把 `?workspace=` 取到的 `''` 当显式覆盖，而 `identity.js` 只把 `undefined` 视为"未给"。live 面板默认身份 `workspace=""`、`workspaceSource="default"`，于是默认视图对 workspace 维度**没有任何条件**——得到的是"全分区"。同链路 `/writes`、`/recalls`、`/edges`、`/evolution`、`/recent`、`/search` 同源。
- **证据**：
  - `src/core/backend/base.js:23-35`（`:30` `if (!value) continue`）
  - `src/core/search.js:65-78`
  - `src/host/routes/router.js:181-196`
  - `src/host/identity.js:57-64`
  - 路由注释自称"列表/详情端点必须传身份（跨身份泄漏是 P0）"，与空串语义冲突
- **复现**：
  - `curl -s 'http://127.0.0.1:3080/whale-memory/api/nodes?limit=100&workspace='` → `total=116`，其中 `n1795358097477_6384db99f1` 的 `workspace="/home/hy/网页端聊天"`
  - 对照 `?workspace=web` → `total=115`；`GET /export` 落 116 行，`workspaces={'':115,'/home/hy/网页端聊天':1}`
  - `GET /nodes/n1795358097477_6384db99f1?workspace=` → `ok=true` + 他分区正文
  - harness（config `identity.workspace='web'`）：`GET /nodes?workspace=` 后 backend 收到 `{userId:'u-cfg',roleId:'',workspace:''}` ⇒ 一个 query 参数即把作用域从"配置分区"清成"全分区"
- **影响**：跨工作区读正文与导出；`allowRemote=false` 时需回环可达即可，`allowRemote=true` 时对 LAN 直接成立（此时按远程泄露计量）。
- **修复建议**：区分"未传（`undefined`）"与"显式空串（`''`）"——后者产出 `col=''` 硬条件，前者不覆盖；区分点放在 `identityParams`/`requestIdentity`。补表征测试：缺参与 `?workspace=` 必须给出不同结果。
- **置信度**：高
- **来源**：r3 P0-1

### P1-01 保留期清理在默认身份配置下退化为"全库物理删除"（跨身份删归档节点，无备份）

- **严重度**：P1
- **模块**：`src/core/keeper/handlers.js`（archive handler / `archiveScope`）、`src/host/config.js`、`src/host/identity.js`
- **现象**：`archive` job 的分区口径只读 `config.identity`（三个 volatile 字段，默认全 `''`），不读 `resolveIdentity()`、宿主登录 userId 或会话 workspace。三字段全空时 `archiveScope()` 返回 `sql:''`（= 无条件），`DELETE FROM nodes WHERE status='archived' AND updated_at < cutoff` 因此在自己身份分区之外也物理删行。写入分区实际由 `resolveIdentity()` 兜底（auto 模式 userId 落 `'local'`/宿主 id、workspace 取会话 cwd），与清理口径不同源。
- **证据**：
  - `src/core/keeper/handlers.js:278-281`、`:286-296`、`:300`、`:429-441`
  - `src/host/config.js:19-24`（`identity.mode='auto'`、三字段 `''`）
  - `src/host/identity.js:108-125`
  - 现有用例把全局清理写成期望：`test/data/keeper.test.mjs:466-468`
- **复现**：`node /tmp/r1-correct/probe-archive-scope.mjs`（真实 `Config({privacy:{retentionDays:1}})`，alice/bob/共享各一条 2 天前 archived）→ `{"deleted":3,"remainingRows":[],"auditReason":"... deleted=3; scope=all"}`；删除前无 `VACUUM INTO`，事后只有一行 `writes(ARCHIVE, scope=all)`。
- **影响**：`privacy.retentionDays>0` 且身份未手工固定时，删别人的归档，不可逆。live 现为 `retentionDays=0`、`identity.workspace=""`（未触发；日志有 `scope=` 可判）。
- **修复建议**：清理作用域与写入同源（走 `resolveIdentity`）；auto 模式或空三元组拒绝执行并返回 `skipped:'identity_auto_unsafe'`（fail-visible）；`archiveScope` 对全空身份返回 `null` 而非 `sql:''`，全局清理改为显式 `payload.scope='all'`；物理删前 `PRAGMA wal_checkpoint(TRUNCATE)` + `VACUUM INTO <dataDir>/backup/whale-<ts>.db`，审计行写备份路径。
- **置信度**：高
- **来源**：r1 F1、r3 P2-1
