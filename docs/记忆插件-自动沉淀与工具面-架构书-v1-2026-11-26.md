## 1. 目标与验收

厂长口径（2026-11-26 15:49）：**普通记忆是为了记录、避免再犯、下次做得更好；默认人工审批是设计错误。只有铁律需要本人同意。**

| # | 目标 | 验收（真产物，不靠 200/测试绿） |
|:--|:--|:--|
| G1 | 收尾普通记忆默认**自动入库**：价值闸→歧义→判重/冲突/保护面→落 active；全程 before/after 审计与可回退状态 | 真实收尾：durable 得 active；task/stale 得 REJECT；歧义得 REVIEW；同文 NOOP；包含超集 MERGE；冲突 SUPERSEDE；保护面 REVIEW；无“正常项被静默存成 CANDIDATE” |

## 4. 目标流程（收尾与主动写入）

```
采集/主动工具 ──► process.__ingest 前置闸（唯一）
   ├─ 身份：userId/workspace 空 → REJECT identity_required（无正文）
   ├─ stale/task → REJECT（task 且 dropTaskInstructions=false 时 CANDIDATE）
   ├─ 歧义/主观/低置信 → CANDIDATE
   └─ durable → auto + reviewToCandidate
                        ▼
                 kind 分流：rule → 提案（pending）；open_loop → 报告；普通 kind
                        ▼
             writer.decide（同身份）：hash NOOP／包含 MERGE／近文 REVIEW／矛盾 SUPERSEDE／protected REVIEW
                        ▼
        ADD/MERGE/SUPERSEDE → active + writes 审计 + evolution
        REVIEW（auto）→ CANDIDATE（审核队列）
```

主动工具 `memory_remember` 走同一 `ingestPolicy`；`memory_update` 走 `updateNode`（保护面/CAS）；`memory_read` 只读；`memory_forget` 只 ARCHIVE。工具身份固定当前会话，不接受跨分区参数。

**不做**：相对指代删词后入库；超长截断入库；静默覆盖 canonical；语义同义自动合并。

## 5. 契约

### 5.1 配置与优先级

```yaml
wrap:
  ingest:
    mode: auto                 # auto | review
    minConfidence: 0.55
    dropTaskInstructions: true # false 时任务句转 CANDIDATE，仍不入库
tools:
  enabled: true
  maxWritesPerTurn: 5          # 只限 remember/update/forget
maintenance:
  suppressWindows: []          # ["09:00-12:00","14:00-18:00"]；只跳自动 reflect
```

**优先级（唯一实现点 `process.js`）**：

1. `__forceShadow` 或 `ingestPolicy.mode='review'` → shadow（不跑价值闸；=0.7.3 行为）。**身份闸不豁免**：review 只回退价值闸，缺 userId/workspace 仍 REJECT。
2. `__ingest` 存在且 `userId/workspace` 为空 → `REJECT identity_required`（不写正文）。
3. stale/task → `REJECT`；仅 `task` 且 `dropTaskInstructions=false` 时转 CANDIDATE（stale 恒拒）。
4. 歧义/主观 → CANDIDATE。
5. `confidence < minConfidence` → CANDIDATE。
6. 其余 → auto + `reviewToCandidate=true`。

`wrap.autoAccept` 删除：`config.js`、`session-wrap.js`、`95-settings-01.js`（默认表+回传）、`95-settings-02.js`（设置卡）、`locale/{zh,en,ja}.json` 同轮清；迁移只做幂等清理并记 `config_migrated:wrap.autoAccept`。`ingest`/`tools`/`maintenance` 字段 `.volatile()`。

`ingestPolicy` 缺省与配置→policy 映射的唯一真源＝`shared/ingest-policy.js`（`INGEST_DEFAULTS`/`ingestPolicyOf`）；收尾与工具一律 import（S4 reflect 落库时同源接入）；不再各写一份 `auto/0.55/true`。

来源由生产者显式决定（session-wrap/tool/S4 reflect），不设 `sources` 开关。wrap/tool/reflect 写 `source='self'`（tool 可 `'tool'`）；owner 只留给用户手工/导入，避免保护面锁死收尾记忆。

### 5.2 工具契约（最小集）

| 工具 | 参数 | 成功返回（canonical） | 语义 |
|:--|:--|:--|:--|
| `memory_remember` | `{text(必填), level?, memory_type?, tags?}` | `{ok:true, action, id:string|null, reason}` | 走同一 `ingestPolicy`（含 `wrap.ingest.mode=review` 回退），`confidence=1`；`action` 就是 writer 落库词表（ADD/MERGE/SUPERSEDE/NOOP/CANDIDATE），CANDIDATE 时 `id=null`、不落 nodes；任务/一次性句抛 `NOT_MEMORY` |
| `memory_search` | `{query(必填), limit?}` | `{ok:true, hits:[{id,text,level,memory_type,score}]}` | 同身份；limit 1..20 默认 5；空 query 抛 `INVALID_ARGS` |
| `memory_read` | `{id(必填)}` | `{ok:true, node:{...白名单}, edges:[{id,from,to,etype,conf}]}` | 同身份；跨分区 id 抛 `NODE_NOT_FOUND`；节点投影不含 hash/向量/审计内部列 |
| `memory_update` | `{id(必填), text?, level?, tags?, expectedUpdatedAt?}` | `{ok:true, id, updatedAt}` | 至少一项；保护面/正文≤500/CAS；冲突抛 `NODE_CHANGED`，重复活跃正文抛 `DUPLICATE_ACTIVE` |
| `memory_forget` | `{id(必填), reason(必填)}` | `{ok:true, id, status:'archived'}` | 只 ARCHIVE（不物理删）；保护面抛 `PROTECTED_TARGET`；reason 1..200 写进审计行 |

**`action` 不另造词表（B16 修订）**：旧计划写“REVIEW 返回 `action:'REVIEW'`”，但落库/审计的真实 action 是 `CANDIDATE`；工具若映射成第二种叫法，排查时就会出现“工具说 REVIEW、库里有 CANDIDATE”。因此模型侧直接拿到 writer 的 action 字符串，`reason` 保留 `review:*` / `gate:*` 分类码，既有 audit 可原样对账。

- **身份**：`!exec.agent || !header || deriveWorkspace(header)===''` → 抛 `IDENTITY_REQUIRED`（先于任何后端调用）；随后 `resolveIdentity(getIdentityCfg(), hint, getHostUserId(), sessionWorkspace)`，`userId/workspace` 任一为空仍拒。`process.js` 的 `__ingest` 身份闸是最后一道，二者不互相替代。
- **限次**：`agent/pre-step` 的 `turn` 为键（`Map<session,{turn,count}>`，turn 变化清零）；**写工具进入写路径即 +1**（参数/身份/读前置失败不计），超过 `tools.maxWritesPerTurn`（默认 5）抛 `RATE_LIMITED`；`agent/disposed` 删槽。计数是进程内存态（不做持久化排队，非铁律 3 对象）。
- **后端能力闸**：五工具要求后端具备 `write/search/getNode/updateNode`；纯 http 远端协议只有写/检索（且 action 词表是 `ok`），工具面**不注册**并记启动日志（缺哪些能力）；local/hybrid 全支持。理由：没有同身份读改能力时 read 会抛 `TypeError`、write 的远端 action 会破坏成功 output schema——宁可显式不可用，也不给半套工具。
- **后端故障不伪装**：读/写/检索的调用异常与非 `node_not_found` 的业务失败一律收敛成 `BACKEND_FAILED`（`HarnessError`，带短标签/cause）；只有明确 `node_not_found` 才是 `NODE_NOT_FOUND`；检索返回 null/非数组按失败而非“零命中”。
- **幂等归档**：对已归档节点再 `forget` 返回 `ok:true` 但不再发 UPDATE/审计，日志记 `memory_forget noop id=…`（不留“跳过无证据”的静默路径）。
- **边界显式拒**：`tags` 超过 32 个抛 `INVALID_ARGS`（不静默截断）；正文/原因长度同样显式拒。
- **子代理**：判据 `header.origin==='subagent' || delegationDepth>0`（两条都认）。`when` 用于宿主支持准入时的目录级排除；**执行期闸**（`identityOf`）对同一判据再拦一次抛 `SUBAGENT_FORBIDDEN`——2026-11-27 live 实测 rc.5 的 step 准入未调用本注册的 `when`（root/子代理共 0 条诊断），子代理工具仍列出但调用被拒；该闸已真机复测（子代理调用得到 `SUBAGENT_FORBIDDEN`）。
- **开关**：`tools.enabled=false` → 目录级 `when=false`（宿主支持时）+ **执行期 `TOOLS_DISABLED`**（live rc.5 的准入不调用 `when`，执行闸是真正的关闭）；改设置即时生效、不用重挂；`wrap.ingest.mode=review` 只影响 remember 是否自动落库，不改变工具可用性。
- **注册**：根作用域 `ctx.tools.register(definition,{when})`；`inject` 增 `tools`；`index.js` 在 `ctx.effect` 内安装并反注册；`output={schema,render}` 只描述成功形状；宿主 `render` 输出即模型可见内容（含 search 命中的正文），canonical value 只做校验/审计。
- **失败**：一律抛 `HarnessError`（`@deepseek-ai/dsh-error`，与宿主同一类；`dsh-llm` 也再导出它），code 稳定、message 中文、不携带记忆正文/查询原文：`IDENTITY_REQUIRED|RATE_LIMITED|INVALID_ARGS|NOT_MEMORY|NODE_NOT_FOUND|NODE_CHANGED|DUPLICATE_ACTIVE|PROTECTED_TARGET|SUBAGENT_FORBIDDEN|TOOLS_DISABLED|WRITE_DISABLED|WRITE_REJECTED|WRITE_FAILED|BACKEND_FAILED`。不返回 `{ok:false}` 冒充成功。
- **审计**：remember 走 `backend.write({source:'tool',origin:'tool',ingestPolicy})` → `nodes.source='tool'`、`nodes.origin='tool'`、`writes.payload.origin='tool'`；update/forget 走 `backend.updateNode(...,{origin:'tool'})`，审计行 payload 与影子候选同形（`writePayload` 唯一构造），reason=`tool_edit|tool_level|tool_tags|tool_supersede`，归档用调用方 reason。
- **不做** `memory_dream`；不做跨分区参数；不做物理删除。

### 5.3 价值闸、歧义闸与判重（可机械判定）

`classifyDurability(text)` 按序：

1. **stale**：`/0\.\d+\.\d+|schema v\d+|PID \d+|(测试|用例)\s*\d+|active\s*\d+|候选\s*\d+|已装|已生效|待重启|重启后|当前 live|交接件已就位/`。
2. **task**：**句首命令/计划句优先**——`/^(请|帮我|需要你|下个?会话|下一步|本轮|这次先|先|再|记得|务必|去|做|改|修|审查|对比|编写|整合|推进|落地|修复|实现|补|加|删|拆分|验证|测试|检查|确认|执行)/` 或 `/^(下个?会话|待办|未完成|下一步|计划|安排)/`；句内引号里的“必须/应”不影响。
3. **歧义/主观**：`这次|本次|刚才|上面|上次|上一轮|本轮|今天|昨天|目前|现在|当前` 或 `可能|大概|我觉得|似乎|也许|应该` → 归 `uncertain`（REVIEW，优先于 durable）。
4. **durable**：含 `/应|必须|不得|禁止|一律|默认|优先|不能|不要|因为|根因|教训|避免|先查/`。
5. 其余 → `uncertain`。

- stale 恒 REJECT；task → REJECT（dropTaskInstructions=false 时 CANDIDATE）；uncertain → CANDIDATE；durable → auto。
- **歧义不自动改写**（不删词、不替换）；长度由上游 schema 500 拒绝，gate 不再判。
- **判重**（同身份 active）：
  1. 同 hash → NOOP（source 更可信只升级 source）。
  2. 字符袋相同但非 hash 相同（语序/极性可能反转）→ REVIEW `word_order_ambiguous`。
  3. `contradiction` 为真 → 冲突分支（保护面 REVIEW，否则 SUPERSEDE）。
  4. **包含且旧文 ≥8 字** → MERGE（不受 0.85 限；保护面 REVIEW）。
  5. similarity ≥0.85 无增益 → REVIEW `near_duplicate`。
  6. similarity ≥0.7 无增益 → REVIEW `possible_paraphrase`。
- **不做**“关键词骨架”“Jaccard≥0.7 自动 MERGE/ARCHIVE”。语义同义改写（如发布/发版）现有判据识别不了，S1 不承诺；留 0.8.1（模型/embedding）。
- **适用范围**：判重阈值对所有写入路径生效（面板 `/write`、导入、工具、收尾）；`__ingest` 只多一道价值闸/身份闸，不改变判重口径，也不回写旧路径行为。

### 5.7 S3：layer 元数据与首轮画像（契约定稿）

**目标**：让模型在**会话首轮**就知道"这台机器上认定过的偏好/教训/事实"，不靠每次召回碰运气；并给记忆节点一个可检索的分层标签（`fact|lesson|user`）。

#### 5.7.1 schema v7：`nodes.layer`

- `SCHEMA_VERSION=7`；DDL 的 nodes 建表加 `layer TEXT NULL`，同时 `ADDITIVE_COLUMNS` 增 `['nodes','layer','TEXT']`（老库走 `migrateAdditiveColumns` 幂等 ALTER，按 `PRAGMA table_info` 判列，不重复 ALTER）。
- 取值只允许 `fact|lesson|user` 或 `NULL`；**不加 CHECK**（老库 ALTER 加 CHECK 不可行；由写入层保证，读路径把未知值当 `NULL`）。
- **备份 fail-closed（仅 v7 起）**：`openDb` 在 `current < SCHEMA_VERSION` 时先 `backupOnMigrate`；若 `performed===false`，**不执行 v7 迁移**，抛 `migration_backup_failed:<reason>`（`backend.ready=false`，hook/工具按 fail-open 跳过，记忆不拖垮对话）；health 显示该原因。v2→v6 的既有 fail-open 行为不变（历史迁移已在 live 完成）。
- 迁移只加列、不动数据：迁移前后 `count(*)` 必须相等（用例断言）；`layer` 旧行为 `NULL`。
- **导出/导入保真**：`NODE_EXPORT_FIELDS` 末尾加 `layer`；`transfer.js` 的 `IMPORT_INSERT_SQL` 增 `layer` 列与绑定；export→import 往返必须保留 `layer`（旧 JSONL 缺列按 `NULL`）。这条不做＝灾备/迁移会静默丢分层。

| session-wrap | `rule`（只产提案，不落 nodes） | — |
| reflect（S4） | `lesson` / `fact` / `preference` 同表 | 同表 |
| 面板 / 导入 / 工具 / 旧调用方 | 无 kind | `NULL` |

- 映射表 `LAYER_OF_KIND` 落 `src/host/session-wrap/dispatch.js`（与既有 `LEVEL_OF_KIND`/`TYPE_OF_KIND` 同处，一处定义）；`ingestItem({layer})` → `backend.write({layer})` → `insertNodeRow` 持久化——**DB 写列只此一处**。
- MERGE 保留目标节点既有 `layer`（不因一次写入升级/清空）；SUPERSEDE 的新行用本次事件的 `layer`；`layer` 不参与判重/冲突判据。
- `memory_remember` 不暴露 `layer`（模型无 kind，写 `NULL`）；0.8.1 再谈工具层分层。

#### 5.7.3 首轮画像注入（`src/host/profile-context.js`）

- **触发**：`agent/pre-step` 里 `payload.turn === 1` 且该 `sessionId` 未注入过（进程内 `Map<sessionId,text>`；同 session 只算一次）；子代理（`origin==='subagent'||delegationDepth>0`）跳过；身份不可判定跳过；`payload.signal.aborted` 跳过。
- **取数**（同一身份、`status='active'`）：`layer='user'` top 5、`layer='lesson'` top 5、`layer='fact'` top 3；排序 `pinned DESC, weight DESC, updated_at DESC`；只读 `id/text/layer`，不写库、不调模型。
- **渲染**：单一 `systemPrompt.context`，`name='whale-memory:profile'`、`order=129`（召回在 130，画像先于召回）、`interpolate:false`；assemble 阶段只读缓存字符串，**不做 DB 查询**（热路径零 IO）。
- **格式与预算（≤800 码点）**：

```
【长期画像】
偏好：<text>；<text>
教训：<text>；<text>
事实：<text>
```

  逐条累加，超出 800 的条目**整条跳过**（不截半句）；三类都空 → `''`（不注入空块）；文案不含时间戳/得分，保证同身份多次会话的 prompt 前缀稳定（缓存友好）。
- **缓存**：`Map<sessionId,string>`，上限 200（超限淘汰最早），`agent/disposed` 删除；插件 dispose 清空。
- **不做**：`nodes.project`、topic 层、按消息 top-2、压缩后重注入（0.8.1）。

#### 5.7.4 依赖与回退

- 模块边界：`profile-context.js → backend 门面 + shared/config-values + identity.js`；不 import 路由/worker；`index.js` 只接线（`ctx.effect` 安装/卸载）。`hook.js` 零改动（画像用自己的 pre-step 与 context 名，不抢召回的名字）。
- 回退：代码回退即关闭画像（列保留无害）；schema v7 列只增不减；迁移前快照 `~/.dsh/whale-memory/backup/whale-<ts>.db`。
- 风险：首轮画像改变请求前缀（每个会话仅一次）；resumed 会话在进程重启后 `turn>1` 不再补注入（宁可不注入，也不在会话中途改动前缀）；`layer=NULL` 的存量节点不参与画像。

## 6. 失败与可观测

- 自动入库失败（写库/事务）→ item `write_failed:*`，run 失败可见，不静默。
- 价值闸/歧义闸 → `REJECT`/`CANDIDATE` + reason；报告只计数，不打印这些条目的正文。
- 工具限次/身份缺失/子代理/保护面/CAS → 抛 `HarnessError`，code 稳定 + 中文 message；日志无正文。
- UI 收尾卡增三行：`入库 N · 待审 M · 跳过 K`；候选页继续显示 CANDIDATE（都是审核项）。
- 日志：`wrap ingest added=N merged=N noop=N review=N rejected=N`（无正文）；`tool_write action=...`（无正文）。
- wrap 报告：`status==='review'` 条目可列正文（人工审）；`ingested` 只列计数+node id；REJECT 只列分类码。日报不写 query 原文。
