## S1 · 普通记忆自动入库（核心）

改动（预算：dispatcher 拆分新文件 ≤250；不改 distill 判据）：

1. `src/core/writer/decide.js`
   - 新增 `ingestPolicy`（事件级）：`{mode:'auto', minConfidence, reviewOnAmbiguity, dropTaskInstructions}`；仅当 `event.origin` 为 `session-wrap`/`tool` 时，`auto` 覆盖全局 shadow；保护面仍 `REVIEW`。
   - 新增纯函数 `classifyDurability(text)`：`durable | task_instruction | stale_version_fact`（规则可机械判：命令/请求句式、版本计数句式；保守：不确定归 durable→后续 REVIEW）。
   - 新增 `rewriteAmbiguity(text)`：去“这次/刚才/上面/上次/本轮”；去主观前缀；超 200 截断/拒绝；返回 `{ok,text,reason}`。

2. `src/host/session-wrap/dispatch.js`
   - 分流：`rule`→proposal（不变）；`open_loop`→open_loop（不变）；普通 kind→`ingestMemoryItem()`：
     - 价值闸（classify）；拒绝写 `writes REJECT` + reason，item status `rejected:<reason>`。
     - 去歧义（rewrite）；失败 → REVIEW 候选（旧路 forceShadow）。
     - 置信度 < minConfidence → REVIEW。
     - 其余 `backend.write({forceShadow:false, ingestPolicy})`；按返回 action 记 status：`written`/`noop`/`review`。
   - 计数：`countsOf` 扩展 `ingested/reviewed/skipped`；run 表加列？不新增列，写 `distilled_json.counts` + 报告；status 投影从 runs 的 candidates/rule_proposals 现有列 + distilled_json 读。
   - 旧候选迁移：`writes.action='CANDIDATE' AND origin LIKE 'session-wrap%'` 一次性按 S1 规则 ingest（脚本 `scripts/migrate-wrap-candidates.mjs`，幂等、先备份）。

3. 配置：`wrap.ingest.{mode=auto,minConfidence=0.55,reviewOnAmbiguity=true,dropTaskInstructions=true}`；删除 `wrap.autoAccept`（启动迁移：旧 true→mode auto，false→review？按厂长口径默认 auto，旧值仅提示）。

4. UI：收尾卡状态行下增 `入库 N · 待审 M · 跳过 K`；候选页只显示 REVIEW；失败计数复用。

5. 测试（定向文件 `test/host/wrap-ingest.test.mjs`）：
   - 3 durable→active（nodes 行 + audit）；4 task→REJECT；stale version→REJECT。
   - 同文→NOOP 不新增；相似→MERGE 同 id；冲突→SUPERSEDE 旧 active superseded、历史保留；protected→CANDIDATE。
   - 歧义句→REVIEW；低 confidence→REVIEW；rule→proposal 文件不变。
   - 旧候选迁移幂等（跑两遍计数不变）。
   - 全量门禁。

验收：架构书 G1/G3 全过；live 一次收尾产生 active 行、CANDIDATE 仅 REVIEW；报告含 N/M/K 且无正文；回退 `mode=review` 行为=0.7.3。
