## 1. 先回答：embed 是为什么设计的

**不是为网关兼容。** 网关相关的是两处完全不同的东西：

- `sync`（`sync.bridgeUrl` 由 profile 注入本机桥地址）＝与 `ai-router` 网关的**双轨同步/outbox**；
- `backend.mode=http|hybrid`＝把记忆请求发给**外部记忆服务**（协议 `whale-memory/1`）。

`embed` 的设计目的是**语义（向量）召回**：让「换了词但意思一样」的记忆也能被想起。但它是半成品：

- 骨架在 0.4.3/0.5.0 时期随观测闭环一起铺下（`nodes.embedding BLOB`、`vector_state`、`config.embed`、面板组、`vector` job、日报 pendingAge 抑制）；
- **实现从未落地**：`vector` handler 只数 pending 就返回 `skipped:'embed_unavailable'`，不改状态；召回/搜索全仓不读 `embedding`；
- 鲸忆自己的架构书 v3.5 把「向量检索」写进**非目标**（§「非目标」；§5.3 也写明语义同义留 0.8.1 用模型/embedding）。

live 证据：`nodes` 815 行里 `embedding` 非空 **0** 行，`vector_state='pending'` **4** 行（无消费者的滞留）；`sync_outbox` **0** 行、`sync_state` **0** 行。

**判断：embed 是「假功能」，应删（见 §4 T1）。** 与「没有 bridge 的用户能不能通用其他网关」无关——那件事根本不由 embed 承担。

**三者交集（纯记忆插件的最小必需集，9 项，均有实现证据）**：
①模型侧写入+检索工具 ②每轮/会话自动召回注入 ③本地单文件/目录持久化真源 ④分层/分类记忆模型
⑤作用域隔离 ⑥纯词法检索即可成立（无需向量） ⑦去重/冲突/失效处理 ⑧周期性巩固/整理 ⑨零外部服务可跑且无强制 UI。
**不在交集**：规则文件仓+提案、双轨同步/outbox、指标/日报、六页签面板、persona、持久化队列、影子候选审核。

**只有鲸忆完整具备**：规则文件仓（git 真源/墓碑编号/提案/plan-apply/AGENTS 渲染）、双轨同步+outbox、外部后端模式、
日报与采纳率、意图预算、会话收尾成套、影子候选+写审计、持久化作业队列、旧库迁移 dry-run、六页签（含规则/召回/写入页）。
**不是鲸忆独有（避免误判）**：分层、首轮画像、关系边/1 跳扩散、周期巩固（三家都有近似实现）；persona 属独立插件。

## 4. 精简方案

**T1 立即删（假功能，小手术）**：embed/向量
- 删：`config.embed` 组、面板「向量嵌入」组与三语文案、`vector` keeper job 与 `JOB_KINDS` 项、日报 `embedEnabled` 分支、`/stats.vector_pending`。
- 留：`nodes.embedding`/`vector_state` 两列**保留为预留列**（SQLite `DROP COLUMN` 会被 `vector_state` 自身 CHECK 引用挡住，重建 nodes 表风险 > 收益）；在 schema 注释登记「预留，代码零引用」。
- 影响：面板少一组、少一个永假开关；无行为变化（该功能本就无实现）。

**T2 冻结（不删、不加功能，进延后清单）**：`sync` 双轨同步、`backend.mode=http/hybrid`。
- 现役默认关（sync.enabled=false、backend.mode=local），live 零使用；删除面 2.3k 行 + 路由/测试面广，收益低于回归风险。
- 冻结口径：面板保留但标注「需网关/外部服务」；不再扩测试、不再改协议。

**T3 保留冻结**：规则子系统（10.9k 行）。
- 依赖：`~/.dsh/rules` 真源 + AGENTS 摘要 + 提案流程是厂长日常；删＝破坏工作流，拆仓＝另立项目。
- 冻结口径：只修 bug，不加功能；提案/镜像/渲染判据不再演进。
